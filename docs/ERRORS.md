# エラー対応ガイド

エラーが出たら、 **黒い画面（コンソール）の一番下あたりに出ている「エラー名」** をこの表から探してください。
エラー名は `SalesforceReportIDNotFoundError` のような英語の単語です。

comken の例外は comken の `docs/ERRORS.md` を参照してください。 このファイルは
**soql-collector で頻出する症状と対処** を書きます。

---

## まず試すこと（どのエラーでも共通）

1. 開いている Excel ファイルをすべて閉じて、 もう一度実行する
2. それでもダメなら、 このガイドでエラー名を探す
3. 表にない・解決しない場合は、 **エラーの画面全体をスクリーンショット** して管理者に送る

---

## soql-collector で頻出する症状

| 症状 | 意味 | 自分でできる対処 |
|---|---|---|
| `実行.bat` を引数付きで動かしたら `終了コード 2` で「 引数は使いません 」 と表示される | ツールは引数を受け付けない。 管理表の「有効」列で対象を選ぶ | 引数を取らずに `実行.bat` をそのまま起動する |
| `終了コード 2` で「 管理表に『有効』が ○ の行がありません 」 と表示される | 管理表の「有効」列が `○` の行が無い | 管理表を開いて、 取りたいレポートの行の「有効」を `○` にする |
| `終了コード 1` で「 `[failed] 管理番号 N: 〇〇』`」 と表示される | 1 件以上の ID で describe が取れなかった。 他の ID は取れている | メッセージに出た管理番号の原因を確認する。 HTTP 401 / 403 なら認証情報を、 404 ならレポート ID が削除済み、 タイムアウトなら再実行 |
| `[failed] 管理番号 N: Salesforce の接続先を決定できません: ...` | URL のドメインが登録済みの組織に一致しない | レポート管理表の URL を開き直す。 新しい組織の場合は管理者へ（ 組織クラスの追加が要る ） |
| `[failed] 管理番号 N: 管理表の URL からレポート ID を取り出せません: ...` | URL が壊れている | 管理表で `Salesforce URL` 列を開き直す（ Salesforce でレポートを開いたときの URL をそのまま貼り直す ） |
| `[failed] 管理番号 N: JSON の書き出しに失敗しました: ...` | 出力先のディスク・フォルダ・権限の問題 | `[FILES] OUTPUT_DIR` のパスが存在するか、 書き込み権限があるかを確認する |
| `[failed] 管理番号 N: レポート describe に失敗（HTTP 401 / 403）: ...` または `列対応表の取得に失敗（HTTP 401 / 403）: ...` | Salesforce の認証が切れている | `python -m comken cred list` で認証情報を確認し、 必要なら `python -m comken cred gui` で登録し直す |
| `[failed] 管理番号 N: レポート describe に失敗（HTTP 404）: ...` | レポートが削除されているか、 URL のレポート ID が間違っている | 管理表の `Salesforce URL` 列を開き直す。 それでも 404 が出るなら、 Salesforce 上でレポートが削除されていないかを確認する |
| `[failed] 管理番号 N: Salesforce への接続でエラー（HTTP ...）: ...` | 接続時の HTTP エラー（ 認証以外 ） | ネットワークの状態を確認して再実行する |
| `[failed] 管理番号 N: Salesforce エラー: ...` | comken の `SalesforceError` | メッセージに表示された指示に従う |
| `python -m trial.fetch_one_report` を引数なしで実行して `終了コード 2` で「 the following arguments are required: url 」 が出る | argparse が使い方を出して `SystemExit(2)` を投げる | URL を渡す（ `python -m trial.fetch_one_report <URL> [管理番号]` ） |

## 警告（ `warnings` ）

JSON の `warnings` にメッセージが残る場合は、 describe は取れているけれど何か
注意点があるケースです。 失敗ではないので、 そのまま SOQL の組み立てに使えます。
例:

- 「主オブジェクト `Opportunity` の describe に失敗したため関連オブジェクトは取得していません」 → 主オブジェクトの列は使えないので、 その JSON は部分的にしか使えない
- 「関連オブジェクトが 50 件あり上限 40 を超えたため、 次の 10 件は取得しません: ...」 → `[LIMITS] RELATED_MAX` を増やすか、 `[LIMITS] RELATED_DEPTH` を下げるか、 不要な関連を許容する。 `関連表.csv` にも `項目表.csv` にも該当行・項目は出ない

## 分類（ まとめて捕捉する用 ）

次の名前は、 似たエラーをプログラム側でまとめて扱うための分類です。
これらの名前が単独で表示されることはありません。 対処するときは、 画面に表示された
具体的なエラー名（ 例: `SalesforceRequestError` ） を上の表か comken の
`docs/ERRORS.md` から探してください。

| 分類名 | まとめるエラー |
|---|---|
| `ComkenError` | comken が出す固有エラー全体 |
| `SalesforceError` | Salesforce に関するエラー。 具体的な状況はメッセージに出る |
| `ConfigError` | config.ini に関するエラー。 具体的な状況はメッセージに出る |

## それでも解決しないとき

以下をセットで管理者に送ってください。

1. エラー画面全体のスクリーンショット（ 黒い画面の文字が読める状態で ）
2. 何をしようとしていたか（ 例: 「朝の売上レポート作成を実行した」 ）
3. いつから起きているか（ 例: 「昨日までは動いていた」 ）
4. `OUTPUT_DIR` の管理番号 JSON （ 認証情報は除く ）
