# 仕様書

## 1. 目的

Salesforce のレポートごとに、 レポート describe と 主オブジェクト +
関連オブジェクトの describe を取って **メモリ上の記録 （ ``ReportRecord`` ）**
にし、 そこから AI に SOQL を組んでもらうための小さな CSV（ **対応表** /
**項目表** / **関連表** / **条件表** / **集計表** / **警告表** / **列名の対応** ）
を生成する。 SOQL を自動で組み立てる機能は持たない。
人が確認してから使う前提である。

## 2. 処理フロー

```
実行.bat / python main.py [引数なし]
   ├─ argv に何か入っていたら -> エラー（ 終了コード 2 ）
   ├─ comken.runtime.is_dry_run() が真なら -> 接続も書き込みもせず、
   │   管理番号・レポートID・出力先をログに出すだけ （ 終了コード 0 ）
   ├─ 管理表 ( Excel ) を読む
   │   → 「有効」が ○ の行を全部対象にする
   │   → 0 件 -> 終了コード 2
   └─ 取得と組み立て
       ├─ ID ごとに:
       │   URL から reportID を取得
       │   site_for(url) で組織のクライアントを開く
       │   report.describe(report_id) でレポート describe を取得
       │   describe_object(主オブジェクト) で主オブジェクト describe を取得
       │   主オブジェクトの参照項目から関連オブジェクトを RELATED_DEPTH 段まで
       │   幅優先で掘る
       │   ReportRecord ( frozen dataclass ) に詰めて返す
       │   **JSON は書かない**
       └─ CSV:
           ReportRecord の一覧から、 OUTPUT_DIR に
             対応表.csv / 項目表.csv / 関連表.csv /
             条件表.csv / 集計表.csv / 警告表.csv / 列名の対応.csv
           を書き、 取れた ID があるときは
             対応表_{管理番号}.csv / 列名の対応_{管理番号}.txt
           も書く
```

## 3. ReportRecord の形（ メモリ上の記録 ）

### トップレベル

```python
@dataclass(frozen=True)
class ReportRecord:
    key: str            # 管理番号
    summary: str        # 概要
    report_id: str      # レポート ID
    url: str            # レポート URL
    main_object: str | None  # 主オブジェクト名（ 取得失敗なら None ）
    report: dict[str, Any]   # レポート describe を slim した dict
    objects: dict[str, dict[str, Any]]  # 主＋関連オブジェクト describe を slim した dict
    relations: tuple[RelationRecord, ...]  # 主＋関連オブジェクト同士の参照
    column_map: list[dict[str, str]]  # 列対応表
    warnings: tuple[str, ...]  # 警告メッセージ
```

### `report`

`client.report.describe(report_id)` の戻り値を **allowlist 方式** で絞った
もの。 次の **2 つのキーだけ** 含む:

| キー | 型 | 意味 |
|---|---|---|
| `reportMetadata` | dict | 元の `reportMetadata` のうち、 `REPORT_METADATA_KEYS` （ SELECT / WHERE / 日付 / サブクエリ / GROUP BY / 集計 / ORDER BY / 件数 / 独自グループ / 独自計算式に必要な 21 個 ） にあるキーだけを**そのまま**残した dict |
| `reportExtendedMetadata` | dict | `detailColumnInfo` / `groupingColumnInfo` / `aggregateColumnInfo` の 3 キーだけを**そのまま**残した dict |

許可リストで落としたキー名は **この dict には残さず**、 `warnings` に
「 レポート定義の中で使わなかったキー: k1, k2, k3 」 の形で 1 行入れる
（ SOQL 組立に必要なものを落としていないか、 最初の本番実行で確かめる用 ） 。

`reportMetadata` / `reportExtendedMetadata` が無い / dict でない / `None`
/ 文字列でも例外を上げない（ そのキーは結果に出ない ） 。

### `objects`

`describe_object` の戻り値を **allowlist 方式** で絞ったもの。 各オブジェクトは
次の 4 キーだけ:

| キー | 型 | 意味 |
|---|---|---|
| `name` | str | オブジェクト API 名 |
| `label` | str | オブジェクト表示名 |
| `custom` | bool | カスタムオブジェクトか |
| `fields` | list[dict] | 項目を **slim した** 形（ 下の ``fields`` セクション ） |

`childRelationships` / `recordTypeInfos` / `urls` / `supportedScopes` /
`layoutable` などの重いキーや管理用キーは**最初から record に入らない**。

### `fields` （ 各項目 ）

各項目は次の **8 キーだけ** （ **この順** ）:

| キー | 型 | 意味 |
|---|---|---|
| `name` | str | 項目 API 名 |
| `label` | str | 項目表示名 |
| `type` | str | 項目の型 |
| `custom` | bool | カスタム項目か |
| `referenceTo` | list[str] | 参照先のオブジェクト名（ ポリモーフィックなら複数 ） |
| `relationshipName` | str \| None | リレーション名（ SOQL で `Account.Name` のように辿る名前 ） |
| `picklist` | list[str] | 元の `picklistValues` のうち `active` が真の `value` を最大 30 件 |
| `picklistTotal` | int | `active` な選択肢の総数（ `picklist` が 30 件に切られているとき、 後ろにどれだけ省略されたか ） |

`picklistValues` / `inlineHelpText` / `length` などのキーや、 配列の項目詳細
（ `controllerName` など）は record に出ない。 関連項目と名前を保存しない
ので、 関連オブジェクト収集は **slim 前** の `referenceTo` /
`relationshipName` で行う。

### `relations`

``RelationRecord`` の tuple （ 主＋関連オブジェクト同士の親→子参照 ）。 各
要素は `parent` / `field` / `relationship_name` / `child` / `depth` を
持つ。 ポリモーフィックな参照は `referenceTo` のエントリごとに 1 本ずつ。

### `column_map` の各行

| キー | 型 | 意味 |
|---|---|---|
| `列キー` | str | レポートの列キー |
| `表示名` | str | 列の表示名 |
| `所属オブジェクト` | str | その項目を持つオブジェクト名 |
| `対応フィールドAPI名` | str | 解決できた SOQL 名（ 関連経由ならリレーション鎖つきドット記法 ） |
| `型` | str | 項目の型 |
| `参照先オブジェクト` | str | 所属オブジェクト側で `referenceTo` を `|` 区切り |
| `リレーション名` | str | 所属オブジェクト側で `relationshipName` |
| `備考` | str | 「関連オブジェクト経由」「列キーの接頭辞で絞り込み」「複数候補あり: ...」「対応フィールドなし」 等の注記 |

## 4. 関連オブジェクトの決め方

主オブジェクト describe の `fields` から次の条件に合う項目を抜き出し、
その `referenceTo` を **`RELATED_DEPTH` 段まで幅優先** で集める。

- `relationshipName` が空でない （ SOQL で `Account.Name` のように辿る名前がある ）
- `referenceTo` が空でないリスト
- ポリモーフィックな参照はリスト内の全エントリを採用

掘り方は **幅優先** :

- 0 段目 = 主オブジェクト自身。 1 段目は主オブジェクトの参照、
  k+1 段目は k 段目で取ったオブジェクトの参照を掘る
- 一度取った（ または取ろうとした ） オブジェクトは重複して取りにくい。
  主オブジェクト自身は最初から対象外 （ `visited` に最初に入れておく ）
- 循環参照（ A→B→A など ） は **既出なので掘らない** で止まる
- `RELATED_DEPTH` 段目まで掘る （ `1` なら 1 段だけ、 今までの挙動 ）

件数は `[LIMITS] RELATED_MAX` で **全段の合計** を打ち切り、 超えた名前は
`warnings` に残す。 近い段から優先的に取るので、 深い段のものは自動で諦める。
警告の形式:

```
関連オブジェクトが {全体} 件あり上限 {RELATED_MAX} を超えたため、
{スキップ数} 件は取得しません: {名前, ...}
```

`skipped` は **重複を除いた出現順**。 同じ名前が複数回候補になっても 1 回しか
数えない。

主オブジェクトの describe 自体が HTTP エラー（ 401 / 403 以外 ） で取れなかった
ときは `主オブジェクト: null` とし、 関連オブジェクトは取らない（ 警告は残る ）。

`relations` には **取れたオブジェクト同士の参照** だけが出る。 BFS で
「 どのオブジェクトを取ったか 」 を決めたあと、 別の処理で主＋関連オブジェクト
の `fields` を 主→関連（ 段順 ） の順でたどって組み立てる。 1 行が 1 本の
親→子の参照で、 次の形:

```
RelationRecord(
    parent=親オブジェクト API 名,
    field=参照項目の API 名,
    relationship_name=relationshipName （ 無ければ None ）,
    child=子オブジェクト名,
    depth=子の段 （ 主 = 0 ）,
)
```

行の `段` は **子の段** （ 主 = 0 ）。 主＋関連の **取れた** オブジェクト
同士の参照を **全部** 載せる。 つまり、 主オブジェクト自身への参照
（ 例: `Account.TaskId → Task`） や自己参照 （ 例: `Account.ParentId →
Account`） も **出る** 。 並びは「 浅い方の親 （ 主→段順 ） → 同じ
親内では項目の出現順 」 。 ポリモーフィック参照は `referenceTo` の各
エントリごとに 1 行ずつ。 同じ `（ 親, 項目, 子 ）` は 1 行。 上限で
打ち切られた子、 describe 取得に失敗した子、 `RELATED_DEPTH` の外側は
**行に含まれない** （ `warnings` か error log に名前だけ残る ） — 親としても
子としても行に出ない。

## 5. CSV の列

### 対応表（ `対応表_{管理番号}.csv` / `対応表.csv` ）

| 列 | 中身 |
|---|---|
| `管理番号` | record の `key` |
| `概要` | record の `summary` |
| `レポートID` | record の `report_id` |
| `レポートタイプ` | `record.report["reportMetadata"]["reportType"]["type"]` |
| `主オブジェクト` | record の `main_object` （ `None` のときは空文字 ） |
| `列キー` | `column_map` の `列キー` |
| `表示名` | `column_map` の `表示名` |
| `所属オブジェクト` | `column_map` の `所属オブジェクト` |
| `対応フィールドAPI名` | `column_map` の `対応フィールドAPI名` （ `"(不明)"` はそのまま ） |
| `型` | `column_map` の `型` |
| `参照先オブジェクト` | 対応フィールドが参照項目のとき、 所属オブジェクト側の `referenceTo` を `|` 区切りで。 そうでなければ空 |
| `リレーション名` | 同じ項目の `relationshipName` |
| `備考` | `column_map` の `備考` |

### 項目表（ `項目表.csv` ）

| 列 | 中身 |
|---|---|
| `オブジェクト` | オブジェクトの API 名 |
| `段` | 主オブジェクトは `0`、 関連オブジェクトは `relations` の `段` 列の値（ 1 / 2 / … ） |
| `オブジェクト表示名` | describe の `label` |
| `項目API名` | `name` |
| `項目表示名` | `label` |
| `型` | `type` |
| `参照先オブジェクト` | `referenceTo` （ 複数は `|` 区切り ） |
| `リレーション名` | `relationshipName` |
| `カスタム` | `custom` が真なら `○`、 そうでなければ空 |
| `選択肢` | `picklist` の値を `|` 区切りで（ 最大 30 件、 `picklistTotal` が 30 を超えるとき末尾に `…` を 1 個 ） |

並びは「 record の `objects` のキー名の昇順 → describe の `fields` の並び順 」 。

### 関連表（ `関連表.csv` ）

| 列 | 中身 |
|---|---|
| `管理番号` | record の `key` |
| `親オブジェクト` | 親オブジェクト API 名 |
| `参照項目API名` | 参照項目の API 名 |
| `リレーション名` | 参照項目の `relationshipName` |
| `子オブジェクト` | 子オブジェクト API 名 |
| `段` | **子の** 段 （ 主 = 0 ） |

並びは **管理番号 → 段 → 親の出現順** 。 取れたオブジェクト同士の参照は
全部載り、 主オブジェクトへの参照や自己参照も含まれる。 上限で打ち切られた
子・ `describe` 取得に失敗した子はここにも出ない。 ポリモーフィック参照は
`referenceTo` のエントリごとに 1 行ずつ。 同じ `（ 親, 項目, 子 ）` は 1 行。

### 条件表（ `条件表.csv` ）

1 レポートを **複数行に分ける** （ 管理番号 → 種別ごとに 1 行 ） 。

| 列 | 中身 |
|---|---|
| `管理番号` | record の `key` |
| `概要` | record の `summary` |
| `レポートID` | record の `report_id` |
| `種別` | `絞り込み` / `組立式` / `日付` / `標準フィルタ` / `クロス` / `上位N` |
| `番号` | 種別ごとの連番 （ `絞り込み` なら `1` から ） |
| `列キー` | 絞り込み列キー または 日付列キー |
| `項目` | 対応表で解決した SOQL 名 （ `絞り込み` のとき、 解決できなければ空 ） |
| `演算子` | 絞り込み演算子 |
| `値` | 値 （ `組立式` は `1 AND (2 OR 3)` のまま、 `日付` は `開始〜終了`、 `クロス` は `primaryEntityField operator relatedEntity.relatedEntityJoinField (criteria)` の 1 文字列 ） |
| `備考` | `日付` の `durationValue` 等 |

### 集計表（ `集計表.csv` ）

| 列 | 中身 |
|---|---|
| `管理番号` | record の `key` |
| `概要` | record の `summary` |
| `レポートID` | record の `report_id` |
| `種別` | `形式` / `グルーピング(行)` / `グルーピング(列)` / `集計` / `並び順` / `バケット` / `独自計算式` |
| `順` | 種別ごとの連番 |
| `名前` | グルーピング名・集計式・列キー・名前（ バケット ）・計算式 |
| `内容` | 並び順やバケット値（ JSON 文字列 ）・独自計算式のラベル |

### 警告表（ `警告表.csv` ）

| 列 | 中身 |
|---|---|
| `管理番号` | record の `key` |
| `概要` | record の `summary` |
| `レポートID` | record の `report_id` |
| `警告` | 1 警告 1 行 （ 例: 「 レポート定義の中で使わなかったキー: ... 」 や 「 関連オブジェクトが 50 件あり上限 40 を超えたため、 次の 10 件は取得しません: ... 」 ） |

### 列名の対応（ `列名の対応.csv` / `列名の対応_{管理番号}.txt` ）

`COLUMN_NAMES = {"Amount": "金額", "Account.Name": "取引先名"}` をダウンローダー
側に貼るための材料。 解決できた列だけが出力対象。

- **CSV** … 解決できた列を 1 行ずつ、 表示名が重複する列は備考に `表示名が重複`
- **テキスト** … Python の dict 本文 （ `COLUMN_NAMES = {` で始まり 4 スペース
  インデント、 UTF-8 ） 。 解決できなかった列は `# 未対応: 列キー / 表示名 / 理由`
  のコメント行で末尾に並ぶ。 表示名が重複する列は同じ行の末尾に
  `# 表示名が重複: 要修正`

## 6. CSV の書き方

- UTF-8 BOM つき （ `utf-8-sig` ） + CRLF
- comken の `CSV` クラス （ `comken.toolbox.csv` ） で書き出す。 comken の
  `CSV._write` は途中で失敗したら `.part` 一時ファイルが片付けられ、
  既存の同名ファイルは無傷で残る
- 文字コードは Excel でそのまま開ける形式に固定
- 失敗した record （ `record is None` ） の per-id CSV は作らない。 全体
  CSV は取れた record だけから組み立てる

## 7. 失敗の扱い（ ID ごと・終了コード ）

| 失敗ケース | 振る舞い |
|---|---|
| 引数が付いている | 終了コード `2`、 何も取らない |
| 管理表に「有効」が `○` の行が無い | 終了コード `2` |
| `report_id_from_url` が `SalesforceReportIDNotFoundError` を上げた | その ID だけ失敗（ `status="failed"` ）。 他の ID は続ける |
| `site_for(url)` が `ComkenError` （ `SalesforceError` 含む ） | その ID だけ失敗。 他の ID は続ける |
| レポート describe の `SalesforceRequestError` | その ID だけ失敗 |
| 主オブジェクト describe の **401 / 403** | その ID だけ失敗（ record は作らない ） |
| 関連オブジェクト describe の **401 / 403** | その ID だけ失敗 |
| 主オブジェクト / 関連オブジェクト describe の **401 / 403 以外の HTTP エラー** | 警告にして他のオブジェクトは続ける（ record は作られる ） |
| CSV 書き出しの失敗 | `run_tables` が例外を投げるが、 `run` 側で握ってログに残す （ record は取れているので、 全体は失敗扱いにしない ） |

`run` の終了コードは、 失敗が **1 件でも** あれば `1`、 全件成功なら `0`、
引数エラー / 設定・対象の不足は `2` 。

## 8. ログに出すもの

- CSV の書き出し: ファイル名と行数
- Salesforce への接続エラー: HTTP ステータスコード + 詳細

describe の中身 （ `fields` の `name` や `picklist` の値 ） はログに出さない
（ 機微な情報が漏れないように ） 。

## 9. 構成

```
main.py                      ← 薄い入口（ src.run.run() を呼ぶだけ ）
src/
  run.py                     ← 実行 / 管理表 / fetch / tables を束ねる
  fetch.py                   ← 1 ID 分の describe 取得と ReportRecord 組み立て
  master.py                  ← レポート管理表（ Excel ） を読む
  settings.py                ← config.ini から Settings を読む
  mapping.py                 ← 列対応表の組み立て ( pure 関数 )
  tables.py                  ← ReportRecord から CSV 各種を生成
trial/
  fetch_one_report.py        ← 単品サンプル （ python -m trial.fetch_one_report ）
tests/                       ← pytest
docs/
  使い方.md                  ← セットアップ・実行例・CSV の読み方
  仕様書.md                  ← このファイル
  ERRORS.md                  ← プロジェクト固有のエラー対応
config.ini.example           ← config.ini の雛形（ 実体の config.ini は git に含めない ）
実行.bat                     ← エントリポイント（ PYTHONPATH を代行、 RPA から呼ばれる ）
```

comken は PYTHONPATH から参照し、 このプロジェクト側では触らない。
