# soql-collector

Salesforce のレポート describe（レポート本体 + 主オブジェクト + 関連オブジェクト）を
**管理番号ごと**にとってメモリに保持して、 SOQL を組み立てるための小さな CSV
（**対応表**・**項目表**・**関連表**・**条件表**・**集計表**・**警告表**・
**列名の対応**・**調査表**・**類似レポート**）を作るツールです。 関連オブジェクトは、
config.ini の `RELATED_DEPTH` 段数まで幅優先で掘ります（既定 3）。 1 段だけ
（ 今までの挙動 ） にしたいときは `RELATED_DEPTH = 1` にしてください。

どのレポートを取るかは管理表の「有効」列が `○` のものすべて。 個別に取りたい
ときは、その行だけ `○` にして、ほかを `×` にします。

調査機能として、 各レポートについて次の 3 つを機械的に判定して CSV に出します
（ **判定は目安** で、 最終判断は人が行う。 曖昧なものは 「 要確認 」 / 「 判定不可 」 に倒す ）：

1. **似たレポートをまとめられるか** （ 同一 / 条件のみ違い / 列のみ違い / 近い ）
2. **2000 件を超えているか** （ 超えている / 超えていない / 判定不可 / 未実施 ）
3. **個人情報を含むか** （ あり / 要確認 / なし ）

**レポートの行データ**（ 個人情報を含みうる ） は **メモリ上で件数を数えるだけ** で、
CSV / ログ / 警告 / 例外メッセージには絶対に出さない。

SOQL はツールが自動生成するのではなく、 **AI にチャットで組んでもらう**
ための材料（CSV 各種）を用意するところまでをこのツールが担当します。
AI が出した SOQL は、本番で実行する前に人が確認してください。

## セットアップ

1. Python 3.11 以上を用意する
2. `config.ini.example` を `config.ini` にコピーし、 `[FILES] MASTER_XLSX_PATH`
   / `OUTPUT_DIR`、 `[LIMITS] RELATED_MAX` / `[LIMITS] RELATED_DEPTH`、
   `[SF] CREDENTIAL_PREFIX`、 必要に応じて `[CHECKS] ROW_LIMIT` /
   `[PII] KEYWORDS` / `[PII] OBJECTS` / `[SIMILAR] COLUMN_SIMILARITY`
   を書き換える （詳細は [docs/使い方.md](docs/使い方.md)）
3. comken の親（既定 `F:\dev`）を `PYTHONPATH` に含める。 `実行.bat` を
   使うと PYTHONPATH の設定を代行してくれる

## 使い方

`実行.bat`（または `python main.py`）を **引数なしで** 実行する。 取られた
レポートは、 管理表の「有効」列が `○` のものすべて。 個別に取りたいときは、
その行だけ `○` にして、 ほかを `×` にする。

終了コードは `実行.bat` がそのまま返す。 RPA から呼ぶのも `実行.bat` を
そのまま起動すればよい）。

- `0` … 全件成功
- `1` … 失敗した ID が 1 件以上ある
- `2` … 引数が付いている / 管理表に「有効」が `○` の行が無い

**引数を付けるとエラーになる** （終了コード 2）。 サブコマンドは無い。

### 単品で試す

レポートを 1 件だけ取りたいときは `trial/` ディレクトリのサンプルが使える
（管理表を読まずに URL を直接指定する形）。

```
python -m trial.fetch_one_report <レポートのURL> [管理番号]
```

出力は `output/single/{管理番号}/` 配下に CSV が書かれ、本体の `output/` は
汚さない。 詳しくは `docs/使い方.md` を参照。

## 出力ファイル

`[FILES] OUTPUT_DIR`（既定 `./output`）に次の 10 種類が置かれる。

| ファイル | 中身 |
|---|---|
| `対応表_{管理番号}.csv` | その管理番号の、**レポート列 ⇔ フィールド** の対応（1 列 1 行）。 末尾に `個人情報` / `個人情報の根拠` 列あり |
| `対応表.csv` | 全管理番号を連結した対応表（管理番号昇順） |
| `項目表.csv` | 全 record を集約した「オブジェクト × 項目」のフラット表 |
| `関連表.csv` | **主＋関連** の取れたオブジェクト同士の親→子の参照を 1 行ずつ並べたもの（ 管理番号 → 段 → 親の出現順 ） |
| `条件表.csv` | レポート定義の絞り込み・組立式・日付・標準フィルタ・クロス・上位 N を 1 行ずつ展開 |
| `集計表.csv` | 形式・グルーピング・集計・並び順・バケット・独自計算式を 1 行ずつ展開 |
| `警告表.csv` | 主オブジェクト取得失敗・関連オブジェクト打ち切り・ describe 失敗・ 許可リスト外キー などの警告。 2000 件チェックで 判定不可 だった理由もここに出る |
| `列名の対応.csv` | `COLUMN_NAMES` 貼付用 CSV |
| `列名の対応_{管理番号}.txt` | 同じく貼付用 Python dict テキスト |
| `調査表.csv` | レポート 1 行ずつの一覧。 2000件超 / 個人情報 / 類似グループ / 統合の見込み などを機械判定した結果 |
| `類似レポート.csv` | 似たレポートをグループ化したもの。 同一 / 条件のみ違い / 列のみ違い / 近い の区分と 「 基準との違い 」 が出る。 グループに入らなかったレポートは出ない |

`record` にはレポート describe を **slim した** 形が入る（許可リスト外の
キー名は含まれない）。 `report` の `reportMetadata` は SOQL 組立に必要な
21 キーだけを**そのまま**残し、 `reportExtendedMetadata` は 3 キーだけを
**そのまま**残します。 各オブジェクトは `name` / `label` / `custom` /
`fields` の 4 キーだけ、 各項目は `name` / `label` / `type` / `custom` /
`referenceTo` / `relationshipName` / `picklist` / `picklistTotal` の 8 キー
だけが `record.objects` に入ります。 `picklist` には `active` な値だけが
最大 30 件入り、 `picklistTotal` に active な選択肢の総数が入ります。
許可リストでレポート describe から落としたキー名は `warnings` に
「レポート定義の中で使わなかったキー: ...」 という 1 行で出るので、
最初の実行で「必要なものを間違って落としていないか」を確認できます。

`関連オブジェクト` は **1 行 1 本の親→子参照** （ `親 / 参照項目 /
リレーション名 / 子 / 段` ） で、 主＋関連の **取れた** オブジェクト同士で
張られた参照を **全部** 載せます（ 主オブジェクトへの参照、 自己参照も
含む ）。 並びは「 浅い方の親 （ 主→段順 ） → 同じ親内では項目の出現順 」。
行の `段` は **子の段** （ 主 = 0 ）。 ポリモーフィック参照は `referenceTo`
のエントリごとに 1 行ずつ、 同じ `（ 親, 項目, 子 ）` は 1 行。 上限で
打ち切られた子・ describe の取得に失敗した子はここにも `項目表` にも出ない。

CSV は UTF-8 BOM つき + CRLF。 Excel でそのまま開けます。
詳細は [docs/使い方.md](docs/使い方.md)・[docs/仕様書.md](docs/仕様書.md)
を参照してください。
