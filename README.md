# soql-collector

Salesforce のレポート describe（レポート本体 + 主オブジェクト + 関連オブジェクト）を
**管理番号ごと**にとってメモリに保持して、 人が Excel で見るブック
``SOQL調査.xlsx`` と、 ダウンローダー用の ``列名の対応.csv`` を作るツールです。
関連オブジェクトは、 コードの定数 ``RELATED_DEPTH`` 段数まで幅優先で掘ります
（ 既定 3、 `src/fetch.py` ）。 1 段だけ（ 今までの挙動 ） にしたいときは
`src/fetch.py` の `RELATED_DEPTH = 1` に直してください。

どのレポートを取るかは管理表の「有効」列が `○` のものすべて。 個別に取りたい
ときは、その行だけ `○` にして、ほかを `×` にします。

調査機能として、 各レポートについて次の 4 つを機械的に判定して xlsx に出します
（ **判定は目安** で、 最終判断は人が行う。 曖昧なものは 「 要確認 」 / 「 判定不可 」 に倒す ）：

1. **似たレポートをまとめられるか** （ 同一 / 条件のみ違い / 列のみ違い / 近い ）
2. **2000 件を超えているか** （ 超えている / 超えていない / 判定不可 / 未実施 ）
3. **個人情報を含むか** （ あり / 要確認 / なし ）
4. **取得できなかった項目は何か** （ 項目 / オブジェクト ）

**レポートの行データ**（ 個人情報を含みうる ） は **メモリ上で件数を数えるだけ** で、
CSV / ログ / 警告 / 例外メッセージには絶対に出さない。

**SOQL の下書きはこのツールで作る** （ 2026-10-15 復活、 安全策つき ） 。
主オブジェクトが取れないとき・組立式が解釈できないとき・履歴スナップショット
があるときは SOQL は未完成になり、 本文の 1 行目に
``【未完成】作れなかった部分があります。このままでは実行できません。`` の
印が付く。 印が付いた SOQL は Salesforce に投げると構文エラーになるため、
レポートより広い範囲を取る危険を物理的に防ぐ。 人が AI に渡して直すか、 印の
付いた SOQL は実行しないこと。 印は定数 ``INCOMPLETE_MARKER`` （
``src/soql_builder.py`` ） で、 ダウンローダー側がこの印を見て実行前に止める。

**SOQL の組み立て方**:

- ``SOQL調査.xlsx`` の ``SOQL`` シートに 1 行 1 レポートで下書きが出る
  （ 列: 管理番号 / 概要 / 主オブジェクト / 状態 / SOQL / 作れなかった部分 /
  要確認 ） 。 1 行目の印もそのまま載る
- ``一覧`` シートの ``SOQLの状態`` 列に ``作成済み`` / ``要確認`` / ``一部作れず``
  / ``作れず`` の状態が出る
- ``OUTPUT_DIR/SOQL資料/{管理番号}.md`` にも ``## SOQL の下書き`` 節が出る
  （ AI への依頼文と、 作れなかった部分・要確認も添える ）

人が組み立てる場合（ 旧手順 ） は ``一覧`` / ``条件`` / ``集計`` /
``項目の対応`` / ``項目一覧`` / ``関連`` シートを AI に渡す。 **必ず人が
確認してから実行する** 。

## セットアップ

1. Python 3.11 以上を用意する
2. `config.ini.example` を `config.ini` にコピーし， `[FILES] MASTER_XLSX_PATH`
   / `OUTPUT_DIR` / `DESCRIBE_CSV_PATH` / `COLUMN_MAP_CSV_PATH` の **4 つの
   キーはすべて必須**。 どれか 1 つでも config.ini に無いと comken が
   `ConfigKeyNotFoundError` （ メッセージにキー名が出る ） で止まる （ 旧
   config.ini に `[LIMITS]` / `[SF]` / `[CHECKS]` / `[PII]` / `[SIMILAR]`
   などのセクションが残っていても無視される ）。 関連オブジェクトの段数・
   2000 件チェック・ 個人情報判定のキーワードなどはコードの定数
   （ `src/fetch.py` / `src/pii.py` / `src/run.py` ） にあるので、
   config.ini.example のコメントを参照
3. comken の親（既定 `F:\dev`）を `PYTHONPATH` に含める。 `実行.bat` を
   使うと PYTHONPATH の設定を代行してくれる

## 使い方

`実行.bat`（または `python main.py`）を **引数なしで** 実行する。 取られた
レポートは、 管理表の「有効」列が `○` のものすべて。 個別に取りたいときは、
その行だけ `○` にして、 ほかを `×` にする。

終了コードは `実行.bat` がそのまま返す。 RPA から呼ぶのも `実行.bat` を
そのまま起動すればよい）。

- `0` … 全件成功
- `1` … 失敗した ID が 1 件以上ある
- `2` … 引数が付いている / 管理表の「有効」が `○` の行が無い

**引数を付けるとエラーになる** （終了コード 2）。 サブコマンドは無い。

### 単品で試す

レポートを 1 件だけ取りたいときは `trial/` ディレクトリのサンプルが使える
（管理表を読まずに URL を直接指定する形）。

```
python -m trial.fetch_one_report <レポートのURL> [管理番号]
```

出力は `output/single/` 配下に xlsx と csv が書かれ、本体の `output/` は
汚さない。 詳しくは `docs/使い方.md` を参照。

「対応が取れなかった列がある（その項目を持つオブジェクトの情報が取れていない）」
ときは `trial/fetch_objects.py` が使える。 ファイル先頭の `OBJECT_NAMES` /
`ORG_URL` を書き換えて `python -m trial.fetch_objects` を実行すると、 各
オブジェクトの describe を 1 回の接続で取り直し（ キャッシュを読まず ） 、
`data/項目定義.csv` のキャッシュに追加し、 `output/single/オブジェクトの
項目.csv` に展開します。

## 出力ファイル

`[FILES] OUTPUT_DIR`（例: `./output`）に次の 4 種類が置かれる。

| ファイル | 中身 |
|---|---|
| `SOQL調査.xlsx` | 人が見る 1 冊のブック。 毎回その回の結果で丸ごと作り直す。 シートは 「 一覧 」 「 取得できなかった項目 」 「 項目の対応 」 「 条件 」 「 集計 」 「 似たレポート 」 「 警告 」 「 項目一覧 」 「 関連 」 「 関係図 」 「 SOQL 」 の 11 枚 |
| `列名の対応.csv` | 全レポート分を **積み上げる** ダウンローダー用 CSV。 `主オブジェクト, SOQL列名, 表示名, 備考, 更新日` の 5 列。 その回に取れた (主オブジェクト, SOQL列名) の行は今回の内容で入れ替わり、 他は残る |
| `SOQL資料/{管理番号}.md` | AI に SOQL を組ませるときに貼る 1 レポート 1 Markdown。 出力する列・組立式・絞り込み・並び順・グループ・集計・関連オブジェクトの経路・ 関係図ファイルへのリンクと字下げツリー・ SOQL の下書き・ SOQL を組むときの注意、 の順。 毎回、 今回取れたレポート分だけ書き直す （ 取れなかった / 失敗した分のファイルは消さない ） 。 UTF-8、 BOM なし、 改行 LF |
| `関係図/{主オブジェクト}.md` | 主オブジェクト単位の木を Mermaid ``flowchart LR`` で書いた Markdown。 Obsidian / GitHub でそのまま図になる。 既存のファイルはそのまま残し、 今回取れた主オブジェクト分だけ上書きする |

**役割分担**:

- `SOQL資料/{管理番号}.md` … **AI に貼る** Markdown
- `SOQL調査.xlsx` … 人が一覧で見る
- `data/列の対応.csv` … 人が手で直して再実行に使う
- `列名の対応.csv` … ダウンローダーが読む

加えて、 `[FILES] DESCRIBE_CSV_PATH` （ 例: `./data/項目定義.csv` ） に
**オブジェクト describe のキャッシュ** が書かれる。 1 行 1 項目、 1 オブジェクト
の行は同じ取得日時。 列は `組織 / オブジェクト / オブジェクト表示名 / カスタム
オブジェクト / 項目 API 名 / 項目表示名 / 型 / 参照先 / リレーション名 / カスタム
項目 / 絞り込み可 / 並べ替え可 / 選択肢 / 取得日時` の 14 列で、 **レコード
の値は入らない** 。 レポートは毎回 Salesforce に聞くが、 オブジェクトの
describe はここに溜めたものを使い、 無いものだけ API から取る。

さらに、 `[FILES] COLUMN_MAP_CSV_PATH` （ 例: `./data/列の対応.csv` ） に
**人が手で見比べる列の対応表** を書く。 自動で取れない列だけ、 人が
Excel で開いて SOQL 列名を直したり空欄を埋めたりする。 列は
`主オブジェクト, 列キー, 表示名, SOQL列名, メモ, 使っているレポート数, 更新日`
の 7 列。 自動で取れた列は次の実行で自動の結果で上書きされ、 置き換えは
WARNING としてログに出る。

- 全部取り直したいときはファイルを消す
- 1 オブジェクトだけ取り直したいときは該当 (組織, オブジェクト) の行を消す
- 組織はレポート URL のホスト名 （ 小文字 ） 単位。 本番と Sandbox が同じ
  ファイルに混ざっても取り違えない

`record` にはレポート describe を **slim した** 形が入る（許可リスト外の
キー名は含まれない）。 `report` の `reportMetadata` は条件・集計・グルーピング
・並び順など機械判定に必要な 21 キーだけを**そのまま**残し、 `reportExtendedMetadata`
は 3 キーだけを**そのまま**残します。 各オブジェクトは `name` / `label` /
`custom` / `fields` の 4 キーだけ、 各項目は `name` / `label` / `type` /
`custom` / `referenceTo` / `relationshipName` / `picklist` / `picklistTotal`
の 8 キーだけが `record.objects` に入ります。 `picklist` には `active` な
値だけが最大 30 件入り、 `picklistTotal` に active な選択肢の総数が入ります。
許可リストでレポート describe から落としたキー名は `warnings` に
「レポート定義の中で使わなかったキー: ...」 という 1 行で出るので、
最初の実行で「必要なものを間違って落としていないか」を確認できます。

`関連オブジェクト` は **1 行 1 本の親→子参照** （ `親 / 参照項目 /
リレーション名 / 子 / 段` ） で、 主＋関連の **取れた** オブジェクト同士で
張られた参照を **全部** 載せます（ 主オブジェクトへの参照、 自己参照も
含む ）。 並びは「 浅い方の親 （ 主→段順 ） → 同じ親内では項目の出現順 」 。
行の `段` は **子の段** （ 主 = 0 ）。 ポリモーフィック参照は `referenceTo`
のエントリごとに 1 行ずつ、 同じ `（ 親, 項目, 子 ）` は 1 行。 上限で
打ち切られた子・ describe の取得に失敗した子はここにも `項目一覧` にも出ない。

`列名の対応.csv` は UTF-8 BOM つき + CRLF。 `SOQL調査.xlsx` は comken の
`Excel` クラス （ `comken.toolbox.excel` ） で書き、 ヘッダー行は太字で
固定される。
詳細は [docs/使い方.md](docs/使い方.md)・[docs/仕様書.md](docs/仕様書.md)
を参照してください。
